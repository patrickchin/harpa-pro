# Analytics & feature flags — PostHog

PostHog is the single tool for two concerns in this repo:

1. **Product analytics** — events and funnels across the marketing
   site, mobile app, and API.
2. **Runtime feature flags** — toggling behaviour (kill-switches,
   gradual rollouts, fixture-mode selection) without a redeploy.

Region: **EU** (`https://eu.i.posthog.com`). One PostHog project,
two API keys (dev and prod), `env` tagged on every event.

## Identity

- **Marketing site:** anonymous PostHog-generated ID stored in a
  first-party cookie, fired post-consent.
- **Mobile pre-OTP:** anonymous device ID generated by the SDK.
- **Mobile post-OTP:** `posthog.identify(userId)` with the
  better-auth user ID. `posthog.reset()` on logout.
- **API:** every event uses the same `distinctId` derived from the
  JWT subject claim. For unauthenticated routes, use the
  `X-Device-Id` header (or skip the capture).
- `person_profiles: 'identified_only'` everywhere to avoid creating
  a profile for every anonymous marketing visitor.

## Event taxonomy

Defined once in
[`packages/analytics-events`](../../packages/analytics-events/src/index.ts).
Snake_case names, snake_case property keys. Adding an event:

1. Add the constant + Zod schema in `index.ts`.
2. Add it to the `EventMap` type and the `eventSchemas` record.
3. Import the constant from every surface that captures it.

Never inline a string literal at a capture site — TS won't catch
drift, and the funnel breaks silently.

## Feature flags

Two categories, both keyed in
[`packages/analytics-events/src/flags.ts`](../../packages/analytics-events/src/flags.ts):

- **Boolean kill-switches** — `twilio-live`, `ai-live`,
  `turnstile-live`, `resend-live`, `api-request-log`.
- **Multivariate mode flags** — `ai-fixture-mode` (replay /
  record / live), `r2-fixture-mode` (replay / live).

### Evaluation strategy (API side)

- `posthog-node` **local evaluation**. Requires
  `POSTHOG_PERSONAL_API_KEY` (Fly secret only — never shipped to
  mobile or marketing). Polls flag definitions on an interval; zero
  per-request network cost.
- **System distinct ID** per environment:
  `system:harpa-api-prod`, `system:harpa-api-dev`. These flags are
  global, not per-user — release conditions in PostHog use
  environment properties, not user properties.
- **Disk cache** on the Fly machine's ephemeral volume. On every
  successful refresh, persist evaluations to JSON. Cold boots
  hydrate from the cache before PostHog responds.
- **Fail-safe defaults** if PostHog is unreachable *and* there is
  no cache: every `*-live` flag = `false`, every `*-fixture-mode`
  = `replay`. Chosen so an outage never accidentally bills a paid
  provider.
- Routes/factories read flags **per-request** (or per short cache
  window), not at module init. Otherwise the migration loses its
  whole point.

### Evaluation strategy (mobile side)

- Bootstrap flags on app start; cache last-known values in MMKV so
  cold starts work offline.
- Re-evaluate after `identify()`.
- Expose a `useFeatureFlag(key)` hook.

## Configuration: what lives where

| Lives in           | Examples                                                                                                                                                       | Why                                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **Doppler (secret)** | `DATABASE_URL`, `BETTER_AUTH_SECRET`, `OPENAI_API_KEY`, `GROQ_API_KEY`, `R2_*` creds, `TWILIO_*_SID/TOKEN`, `TURNSTILE_SECRET_KEY`, `RESEND_API_KEY`, `POSTHOG_*_KEY` | True secrets — credentials, tokens, salts.        |
| **Env (config)**     | `NODE_ENV`, `PORT`, base URLs, `R2_BUCKET`, `R2_ENDPOINT`, `R2_PRESIGN_TTL_SEC`, `MIGRATIONS_REQUIRED_HEAD`, `WAITLIST_*` config                                | Boot-time, infra-shape config. Not secret, but not runtime-toggleable. |
| **PostHog flags**    | `twilio-live`, `ai-live`, `turnstile-live`, `resend-live`, `api-request-log`, `ai-fixture-mode`, `r2-fixture-mode`                                              | Behaviour we want to toggle without a redeploy.    |

When a flag says "go live" but the matching credential is missing,
the collaborator factory **falls back to fixture/stub mode with a
loud warning** rather than crashing the API. Per Pitfall 13, ship an
integration test for each factory that flips the flag via the
in-memory `FlagSource` and asserts the real side-effect path.

## Consent

PostHog uses cookies/identifiers, which means the marketing site's
previous "cookieless, no banner" promise no longer holds:

- **Marketing site:** minimal accept/decline banner. PostHog init
  only fires post-accept. Cloudflare Web Analytics remains
  always-on as the cookieless baseline.
- **Mobile:** one-time onboarding toggle ("Help improve the app",
  default ON), togglable in Settings. Revoking calls
  `posthog.optOut()` and clears queued events.
- **API:** no consent surface — server-side events are operational
  telemetry, not user tracking, and use no cookies.

## Fixture mode kill-switch

PostHog **must not** run in fixture-mode CI/dev runs, or mock
traffic pollutes production analytics.

- Mobile: when `EXPO_PUBLIC_USE_FIXTURES=true`, the analytics
  module exports a no-op client.
- API: when `NODE_ENV=test` or `POSTHOG_API_KEY` is absent, the
  client factory returns a no-op stub. `FlagSource` is the
  in-memory map injected by the test.
- Marketing: PostHog init is gated on consent — fixture/CI
  Playwright runs never click "accept", so no events fire.
