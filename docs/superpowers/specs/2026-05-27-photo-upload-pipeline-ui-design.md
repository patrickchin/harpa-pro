# Photo Upload Pipeline UI — Bluesky-inspired refresh

**Date:** 2026-05-27
**Status:** Design — awaiting plan
**Author:** Brainstorming session
**Related:**
- `docs/v4/arch-batch-photo-notes.md`
- `docs/v4/plan-camera-upload-pipeline.md`
- `apps/mobile/lib/uploads/usePhotoUploadEntries.ts`
- `apps/mobile/components/notes/PhotoNoteCard.tsx`
- `apps/mobile/components/notes/PhotoBatchGrid.tsx`

## Problem

The current photo upload UI was generated by Codex and accreted three
overlapping pending-state surfaces:

1. `PhotoNoteCard.SoloPendingTile` — solo-photo overlay with a progress
   bar pinned to the tile's bottom edge.
2. `PhotoNoteCard.PendingFooter` — a row of `Retry`/`Cancel` buttons
   under the tile/grid with a status-label text that changes through
   five distinct strings during a single upload
   (`Queued → Preparing → Uploading → Saving → Adding to timeline`).
3. `UploadQueueStrip` — a screen-bottom strip showing aggregated
   progress and per-failure retry chips.

This violates the "no shifting UI, no replacing elements" rule the
team explicitly wants to enforce: text under the tile changes five
times, two surfaces compete for the user's attention, and the grid
clips on the right edge in the 3-wide layout because
`PhotoBatchGrid` hard-codes the wrong container-padding constant
(`screenWidth - 32 - 24` when the actual container math is
`screenWidth - 40 - 24`).

The data model also leaks the implementation history: `NoteEntry`
carries both a legacy single-file `pendingUpload` AND a `pendingFiles`
array, and the grid has fallback branches for shapes the hook no
longer produces. Two sources of truth.

## Goal

Bring the photo upload UI in line with the **Bluesky composer**
pattern — the closest open-source analogue in our stack (Expo + RN,
small surface, single attachments array, per-tile controls). The
unifying principle: **the tile IS the surface**. Progress, cancel,
retry, and error all render on the tile itself. The card never
mounts or unmounts a row, never changes text, never shifts.

## Non-goals

- Background uploads (when the app is suspended). Tracked separately;
  may pull in `react-native-background-upload` later.
- Resumable uploads / tus protocol. Not a current pain point.
- Replacing the queue/transport layer (`lib/uploads/queue.ts`,
  `run-upload.ts`, presign/PUT/register/createNote pipeline). The
  state machine stays. Only the UI bindings and the entry-level data
  shape change.
- Per-photo captions. The single `entry.text` body stays as-is.

## Design

### 1. Data model — one `attachments[]` array

Replace the current `NoteEntry` photo-related fields:

```ts
// before
interface NoteEntry {
  fileId?: string | null;
  thumbnailFileId?: string | null;
  files?: ReadonlyArray<{ id; fileId; thumbnailFileId; position }>;
  pendingFiles?: ReadonlyArray<{ jobId; sourceUri; status; progress; error? }>;
  pendingUpload?: { jobId; sourceUri; status; progress; error? } | null;
  ...
}

// after
interface NoteEntry {
  attachments: ReadonlyArray<Attachment>;  // ordered: position for saved, addedAt for pending
  ...
}

interface Attachment {
  /** Stable React key. Matches `f.id` for saved, `jobId` for pending. */
  key: string;
  /** Server file id once registered. Null while pending. */
  fileId: string | null;
  thumbnailFileId: string | null;
  /** Local URI used for the bytes while pending. Null for legacy saved rows. */
  sourceUri: string | null;
  /** True while the upload pipeline still owns this attachment. */
  isPending: boolean;
  /** Upload job id while pending; undefined once saved. */
  jobId?: string;
  /** Pipeline status while pending; undefined once saved. */
  status?: JobStatus;
  /** [0..1] while pending; undefined once saved. */
  progress?: number;
  /** Set when status === 'failed'. */
  error?: string;
  /** Ordering hint. */
  position: number;
}
```

A single ordered array. The grid layouts off `attachments`. The
fullscreen preview layouts off `attachments.filter(a => a.fileId)`.
No more dual-array reconciliation.

`usePhotoUploadEntries` produces synthetic entries with `attachments`
populated from pending jobs; the provider merges with server-returned
entries by overlaying real attachments at matching positions. The
`noteIdToSyntheticId` anti-flicker map is **unchanged**.

### 2. UI primitive — `<PhotoTile>` owns the full lifecycle

One component renders every state. No conditional sub-components.

```tsx
<PhotoTile
  attachment={a}
  size={tileSize}
  onPress={() => preview.open(a.fileId)}
  onCancel={() => queue.cancel(a.jobId)}
  onRetry={() => queue.retry(a.jobId)}
/>
```

Internal rendering:

| State           | Image                  | Overlay                                | Controls                  |
|-----------------|------------------------|----------------------------------------|---------------------------|
| pending, ≤100%  | sourceUri at 60% opacity | centered 28px progress ring             | small `×` top-right (cancel) |
| done            | sourceUri or server URL at 100% opacity | none (faded out over 200ms) | tile press → open preview |
| failed          | sourceUri at 50% opacity, slight red tint | centered red ⚠️ icon | tap = retry; long-press = dismiss |
| empty/loading saved | bg-muted with shimmer  | none                                    | none                       |

Key rules:

- **No status text on the tile.** Confirmation by absence (Signal /
  Bluesky pattern).
- **Same `<CachedImage cacheKey={attachment.key}>`** across the entire
  lifecycle — the cache key never changes, so `expo-image` keeps the
  bytes in its memory cache and the pending→saved transition is a
  pure repaint with no flash, no remount.
- **The dim/ring/× fade out via Reanimated** (200ms ease-out) when
  `isPending` flips false — the user sees the indicator dissolve,
  not snap off.
- **Single tap on a pending tile** is a no-op (not retry, not cancel) —
  the `×` is the explicit cancel target. This avoids accidental
  cancellation while scrolling.

### 3. Grid sizing — measure, don't guess

`PhotoNoteCard` measures its card-interior width via `onLayout` and
passes it down. `PhotoBatchGrid` accepts `containerWidth` as a
**required** prop and computes tile size as:

```ts
const cols = Math.min(items.length, 3);
const tileSize = Math.floor((containerWidth - GAP * (cols - 1)) / cols);
```

No `useWindowDimensions`. No hard-coded padding constants. Works in
any host container (timeline, modal, future split-screen). The 8px
clipping bug in the timeline goes away because the math is now
sourced from actual layout, not constants drifting from upstream
padding changes.

### 4. Components removed

- `UploadQueueStrip` (component + test + integration in
  `ReportTabPane`/`NotesTabPane`/anywhere it mounts). Per-tile is
  the sole surface for in-flight state.
- `SoloPendingTile` (inner component of `PhotoNoteCard`).
- `PendingFooter` (inner component of `PhotoNoteCard`).
- `aggregateStatus` (helper) — no longer needed; per-tile state is
  self-describing.
- `statusLabel` (helper) — no text, no map.

### 6. Animation library

Reanimated v3 (`react-native-reanimated`) for the overlay fade. Already
a transitive dependency of `react-native-gesture-handler` /
`react-native-screens`. No new package.

Spec: 200ms `ease-out` on `opacity` for the dim+ring layer when
`isPending` flips false. Use `useDerivedValue` driven from the
upload-queue snapshot so progress changes drive ring fill without
re-rendering the parent card.

### 7. Progress ring spec

- 28px outer diameter, 3px stroke.
- Background ring: `border-foreground/20`.
- Foreground ring: `border-primary`, animated arc from 12 o'clock,
  clockwise, full circle at progress = 1.
- Implemented as an SVG circle with `strokeDasharray` /
  `strokeDashoffset` animated via Reanimated worklet.
- Hidden when `progress >= 1 && status !== 'completed'` (the
  "finalizing" tail — registerFile + createNote) — instead the ring
  is replaced by a small pulse animation on the dim overlay so the
  user still sees activity but no false 100%-then-jump-back.

### 8. Failure UX detail

- ⚠️ icon: 24px, `text-danger-foreground`.
- Tap target: full tile (44pt min). Tap fires `onRetry`.
- Long-press (500ms): fires `onDismiss` (queue.remove).
- Accessibility: `accessibilityRole="button"` +
  `accessibilityLabel="Photo upload failed. Double-tap to retry,
  long-press to dismiss."` + `accessibilityHint=<error message>`.

### 9. Cancel UX detail

- `×` button: 20px circular tap target in top-right corner of the
  pending tile, 6px inset, `bg-black/50` background, white icon.
- Tap fires `queue.remove(jobId)` and triggers a 200ms scale-out on
  the tile before the entry refreshes off the snapshot.
- Accessibility: `accessibilityRole="button"` +
  `accessibilityLabel="Cancel upload"`.

### 10. Migration / backward compat

Persistence layer (`lib/uploads/persistence.ts`) is unaffected — it
serialises queue jobs, not `NoteEntry`. `NoteEntry` is built from
server data + queue snapshot on every render, so there's no
on-device storage migration. The change is purely in-memory data
shape + UI.

Server API contract is unchanged. The `attachments` array is built
from existing `files` and queue snapshot.

### 12. Accessibility

- Per-tile screen reader labels describe state ("Uploading photo, 62
  percent" / "Photo upload failed" / "Photo, tap to open").
- Progress ring is `accessibilityRole="progressbar"` with
  `accessibilityValue={{ now, min: 0, max: 100 }}`.
- The aggregate-strip's progressbar role moves to the per-tile rings
  — net accessibility coverage is unchanged.

## Open risks

1. **Synthetic-entry merging.** The `GenerateReportProvider` currently
   merges server rows with synthetic upload rows via the
   `noteIdToSyntheticId` map. With a unified `attachments` array,
   the merge must handle the case where the server returns
   `files: [a, b, c]` while the synthetic still has
   `attachments: [pending a, pending b, pending c]` mid-flight.
   The merge must overlay by position, not by index. Plan must
   spell out the merge function and test it explicitly.

2. **Reanimated worklet usage.** SVG-via-Reanimated for the progress
   ring requires `react-native-svg` + Reanimated v3 worklet
   compatibility. We may need `react-native-redash` for the arc math
   if the worklet form is too noisy. Plan should bench the ring
   render cost in the dev-client before committing to SVG over a
   simpler conic-gradient hack.

3. **Anti-flicker preservation.** The map-based React key trick must
   continue to work with the new `attachments` array. The synthetic
   entries' attachment `key` field must equal the eventual server
   attachment id so the grid keys are stable across the transition.
   The mapping currently lives at the entry level; the plan needs
   to extend it to the attachment level.

## Out of scope (documented for future work)

- Per-attachment captions / alt text.
- Drag-to-reorder pending tiles.
- Pause/resume controls on the tile (only cancel + retry for now).
- Background uploads via `react-native-background-upload`.
- Bytes-weighted aggregate progress (no aggregate UI surfaces this
  any more).
